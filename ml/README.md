# Machine-learning priority model

MedOS uses a trained machine-learning model alongside its rule-based triage to decide a patient's priority (Critical, High, Medium or Low), which the scheduler then uses to order the queue.

> **The data is synthetic.** No real patient data is used. The dataset is generated by a script from the project's triage protocol, so it can be shared and regenerated exactly. The results show that the method works; they are not clinical validation.

## Files

| `data/triage_synthetic.csv` | The dataset: 8,000 rows of symptoms, age, sex, pregnancy, vital signs and a priority label |
| `train.py` | Trains and evaluates the model, then exports it |
| `reports/metrics.md` | Evaluation report: accuracy, recall, confusion matrix, comparison with the rules |
| `reports/metrics.json` | The same numbers in machine-readable form |
| `reports/reference_predictions.json` | scikit-learn's predictions, used to check the exported model gives identical answers |

| `../website/ml/triage_model.js` | The same trained model used by the website |
| `../medos/ml_triage.py` | Runs the model on the Pi in plain Python (no scikit-learn needed) |
| `../website/js/ml.js` | Runs the model in the browser |
| `../tests/test_ml.py` | Tests: same answers as scikit-learn, upgrade-only behaviour, scheduler integration |

## The dataset

Each row is one patient visit:

| Column | Example |
|---|---|
| `symptoms` | "Fell down and is not waking since morning" |
| `age`, `sex`, `pregnant` | 70, male, 0 |
| `temp`, `pulse`, `spo2`, `bp_sys`, `pain` | vital signs; blank when not measured (about 40% of rows) |
| `condition` | the protocol condition the row was generated from |
| `phrasing` | `keyword` (protocol wording), `paraphrase` (everyday wording the rules don't contain) or `unclassified` |
| `priority` | the label: `critical`, `high`, `medium` or `low` |

How a row is made:
1. A condition is picked with a realistic mix. After vital signs raise some levels, the labels end up as 41% low, 23% medium, 19% high and 17% critical.
2. It is described with either a protocol keyword or an everyday paraphrase. Paraphrases are what a learned model can handle and fixed keywords can't.
3. Context, minor complaints and occasional negations ("no chest pain") are added.
4. Age and vital signs are sampled, with abnormal vitals more likely in severe cases.
5. The label is the protocol level, raised by danger-level vitals and pregnancy rules. About 2% of labels are shifted by one level to simulate clinicians disagreeing.

## The model

- **Text features:** TF-IDF of words and word pairs from the symptoms.
- **Number features:** age, temperature, pulse, SpO₂, systolic BP and pain score, standardised, plus a "was it measured" flag for each, pregnancy and an age-extreme flag.
- **Classifier:** multinomial logistic regression (scikit-learn), with class weights balanced.

It is small (about 2,300 features), trains in under a second, runs instantly on a Raspberry Pi, and is explainable: every word and vital sign has a visible weight for each level. Reception shows the words that drove each prediction.

## Results (test set: 1,600 held-out synthetic patients)

| Method | Accuracy | Critical recall |
|---|---|---|
| Rules engine alone | 75.8% | 67.1% |
| ML model alone | 95.1% | 87.6% |
| **Rules + ML upgrade (what MedOS uses)** | **96.8%** | **98.2%** |

**Stricter test: phrasings the model never saw.** One phrasing per condition was removed from training entirely, and a separate model was trained without it and tested on the 1,174 rows that use those phrasings. Rules alone scored 69.1%, the model alone 61.8%, and rules + ML upgrade 72.8%. The combination still beats the rules, but the model only partly generalises to new wording. That is expected from a model trained on a limited synthetic vocabulary, and it is why the model is a second opinion and not the decision-maker.

Full details are in `reports/metrics.md`.

## How MedOS uses it

1. The rules engine (`medos/triage.py`) sets the priority.
2. The model predicts the priority with a confidence score.
3. If the model says *more urgent* and is at least **75% confident**, the priority is raised. The reason is recorded on the patient ("ML model: Critical (95% confident) — raised from Low") and in the kernel log as an `ML` line.
4. The model can **never lower** a priority, and it never overrides a level set by staff.

You can switch it off in *Admin → AI assistant → Machine-learning priority model*.

## Reproduce

```bash
pip install -r ml/requirements.txt
python ml/generate_dataset.py   # → ml/data/triage_synthetic.csv
python ml/train.py              # → model files + ml/reports/
python -m pytest tests/test_ml.py
```

The random seeds are fixed, so you get the same dataset and the same numbers. Only training needs scikit-learn; running MedOS doesn't.
