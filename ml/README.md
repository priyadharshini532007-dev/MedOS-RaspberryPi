# Machine-learning triage

MedOS uses a trained machine-learning model alongside its rule-based triage. It reads what a patient said — in **English, Tamil or Tanglish** (Tamil typed in English letters), or a mix — and predicts two things:

1. the **priority** (Critical, High, Medium, Low), which the scheduler uses to order the queue, and
2. the **condition** it understood (one of the 26 protocol conditions) and so the **department**, which booking uses to find a hospital with the right specialist.

> **The training data is synthetic.** No real patient data is used. The dataset is generated by a script from the project's triage protocol, so it can be shared and regenerated exactly. The results show that the method works; they are **not clinical validation.**

## What it achieves

Priority accuracy, rules alone → what MedOS uses (rules, raised by the model):

| Test | Sentences | Rules alone | **MedOS (rules + ML)** | Critical cases caught |
|---|---|---|---|---|
| **Fresh held-out sentences** — written separately from the generator, English / Tamil / Tanglish / mixed | 89 | 59.6% | **98.9%** | rules 47.2% → **100%** (36 of 36) |
| Development sentences (the set used while tuning, so optimistic) | 109 | 80.7% | 98.2% | 71.0% → 100% |
| Held-out synthetic cases | 2,700 | 79.2% | 96.6% | 74.4% → 96.7% |
| **Wording never seen in training** (the hard test) | 1,763 | 67.0% | 84.2% | 46.3% → **66.0%** |

On the fresh sentences it also names the right **condition for 94.4%** and the right **department for 96.6%**. By language, fresh sentences: English 100%, Tamil 100%, Tanglish 95.2% (MedOS priority accuracy).

**Read these honestly:**
- The first, cleaner run on the fresh sentences scored **95.5% with one critical case missed**. I then made general improvements (more negation examples, more phrasings, safety-first thresholds, a negation guard) after looking at those mistakes, so **98.9% is optimistic**. The held-out-wording row, which was not tuned on, is the more sober number.
- On wording the model has never seen, it is **much weaker** (66.0% of critical cases caught, still better than the rules' 46.3%). That is why it is a second opinion next to the rules and staff, never a replacement.
- 36 critical sentences is a small sample: "100%" means 36 of 36, not "always".

Everything is in `reports/metrics.md` and `reports/metrics.json`.

## The dataset

Each row is one patient visit: the `symptoms` text, `lang` (`en`, `ta`, `tl` Tanglish, `mx` Tamil-English mixed), its English `meaning`, age, sex, pregnancy, vital signs (blank when not measured), the `condition` and `department`, and the `priority` label.

How a row is made:
1. A condition is picked with a realistic mix (after vital signs raise some levels: 41% low, 23% medium, 19% high, 17% critical).
2. It is described in one of the four languages, either with a protocol keyword or an everyday phrasing the keyword rules do **not** contain. Tamil rows use spoken Tamil (வலிக்குது, முடியல); Tanglish rows get random spelling variation (valikuthu / valikkuthu / valikudhu); mixed rows put English medical words in Tamil sentences ("எனக்கு chest pain இருக்கு").
3. Context is added (how long, who it is about, a second minor complaint). In 30% of rows a severe symptom is **denied** ("no chest pain", "நெஞ்சு வலி இல்லை", "nenju vali illa") so the model learns that this cancels it.
4. Age and vital signs are sampled; abnormal vitals are more likely in severe cases.
5. The label is the protocol level, raised by dangerous vitals and by pregnancy with abdominal pain. About 2% of labels are shifted one level to simulate clinicians disagreeing.

## The model

- **Text:** TF-IDF of whole words, word pairs (so "நெஞ்சு வலி இல்லை" differs from "நெஞ்சு வலி") and 3–5 character pieces (so Tamil endings — வலி / வலிக்குது / வலியா — and misspellings still match).
- **Numbers:** age, temperature, pulse, SpO₂, systolic BP, pain score, pregnancy, plus a "was it measured" flag for each.
- **Two heads, one text representation:** a **priority** head (words + numbers) and a **condition** head (words only). Both are multinomial logistic regressions — small, quick on a Raspberry Pi, and explainable.
- **Export:** weights are 8-bit integers with one scale per class, so the website download stays small. **Every number above is measured on the exported weights**, the model that actually runs.

## How MedOS uses it

1. The rules engine sets the priority first.
2. The model may only **raise** a priority — never lower one, and never over staff.
3. It acts when it is **sure of the condition**. The more serious the condition, the less sure it needs to be: about 30% for Critical conditions, 40% for High, 55% for the rest. A false alarm costs a little queue priority; a missed emergency can cost a life. (Picked on the held-out-wording test, not on the fresh sentences.)
4. Failing that, the priority head may act alone only if it is ≥ 75% sure **and the condition head leans the same way**. On wording it has never seen, the priority head can be confidently wrong, so the two heads must agree.
5. It **never acts on a symptom the patient denies.** If the text mentions the predicted condition only to deny it ("no chest pain", "நெஞ்சு வலி இல்ல, ஆனா இருமல் இருக்கு"), nothing is raised. The guard deliberately excludes "state" conditions where a negated phrase *is* the emergency ("he is not breathing", "மூச்சு இல்லை").
6. If it recognises none of the words, it gives no opinion. If it only half-understands, the screens say "not sure what this means yet" instead of showing a priority it has no basis for.

The condition it understood also sets the **department** when you book, and explains a Tamil complaint in English when the internet translation is unavailable or wrong. You can switch the model off in *Admin → AI assistant → Machine-learning priority model*.

## Reproduce

```bash
pip install -r ml/requirements.txt
python ml/generate_dataset.py   # → ml/data/triage_synthetic.csv   (deterministic)
python ml/train.py               # → model files + ml/reports/      (about 8 minutes)
python -m pytest tests/test_ml.py
```

The random seeds are fixed, so you get the same dataset. Only training needs scikit-learn; running MedOS does not.
